# GitHub screenshot attachments

Use this procedure when preparing FE AC screenshot evidence. Use an available browser-control tool for the attachment upload; PR creation and metadata edits still use `gh` outside the sandbox.

1. Retain the captured screenshots locally until upload and PR readback succeed. Identify the exact repository and head branch from `gh` metadata, and use the authenticated GitHub browser session for that repository.
2. For an existing PR, open its body editor. For a new PR, open the repository's compare page for the resolved base and head and open the PR form. Use the description editor's attachment/file-upload control to upload each local screenshot. If necessary, inspect the control surface's documented file-upload capability before operating it. This step uploads files only; leave the editor unsaved and do not create the PR through the browser.
3. Wait for each upload to complete and copy the image Markdown inserted into the editor. Retain GitHub's returned attachment URL exactly, together with its AC number and captured state. Inspect the editor preview to confirm that the image matches the intended screenshot. A filename or an upload-in-progress indicator is not a completed attachment.
4. Cancel or discard the unsaved form edits after recording the URLs. Build the complete PR body locally with the uploaded image Markdown in the AC table, then publish it through `gh pr create --draft --body-file <FILE>` or `gh pr edit <PR> --body-file <FILE>` under Opening a PR's freshness rules.
5. Read the published body through `gh` and view the rendered PR in the authenticated browser. Confirm that every expected attachment renders and that repository reviewers have access. Keep the local captures until this check succeeds.

If there is no authenticated GitHub session, no browser file-upload capability, a rejected upload, or an inaccessible returned image, mark the affected AC evidence pending with the specific reason. Continue independent authorized delivery work, retaining the local captures. Never substitute a local path, commit screenshots to the product repository, publish the body through the browser, or claim an unfinished upload succeeded.
